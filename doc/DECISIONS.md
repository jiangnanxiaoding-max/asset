# 关键设计决策

## 1. 决策引擎不使用 LLM

资金与合规决定全部由确定性领域规则产生。LLM 对本题没有必要；如果未来引入，也只能润色已经确定的解释，不能修改处置、原因码或执行动作。这样相同事实和策略版本能够稳定重放，离线环境也能完整运行。

## 2. `TriageCase` 是一致性边界

单笔分诊以 `TriageCase` 为聚合根，状态只能按 `RECEIVED → INVESTIGATING → DECIDED → AUDITED` 转移。决定必须属于同一订单，审计成功前资金移动永远不具备资格。制裁冻结在聚合记录决定时产生领域事件。

没有把调查事实全部塞进聚合：事实来自其他权威源，属于该次决策的不可变快照；应用服务负责协调端口，领域策略只消费快照。

## 3. 题目内嵌到账字段只属于离线 stub

`fiat_status`、deposit 确认数和到账金额来自不可信订单载荷。为了让题目完全离线运行，解析器将其保存为明确标记的 embedded evidence，再由 `Embedded*StubAdapter` 转换为资金事实。生产环境必须替换这些适配器，查询支付网关、链节点或内部账本，领域和应用代码无需改变。

## 4. 提币默认挂起

材料没有钱包余额、入账状态和原子预留记录，因此 `UnavailableWalletFundsAdapter` 永远返回不可用事实。所有 withdrawal 都不能仅凭订单声明自动发币。没有采用“上游已经预留”的乐观假设，因为这会破坏资金守恒。

## 5. Travel Rule 缺省语义

供应材料中完全省略 `counterparty` 的订单按题目 fixture 约定视为客户直接交易，即 `NOT_VASP`；这是为了让明确标注为干净的 O-001/O-002 能形成自动完成候选。只要传入了 counterparty 对象但没有可靠的 `is_vasp`，状态就是 `UNKNOWN`，系统挂起，绝不推断为非 VASP。生产环境应使用 VASP 目录查询端口替换该 fixture 约定。

## 6. 月度限额只做题面可证明的检查

客户文件只有月度上限，没有本月累计已用额度。本实现执行“单笔美元等值不得超过月度上限”，但不声称完成真实累计额度检查。生产环境应增加累计额度端口，并用 `monthlyUsed + currentOrder` 做原子校验。

## 7. 最小金额和金额不匹配

低于最低金额是策略留白，选择 `MANUAL_REVIEW`。少付或多付同样只进入人工/运维处理，不自动部分成交，也不自动退款。退款本身是新的资金动作，需要单独授权和幂等保护。

## 8. 精度和报价

金额统一使用 `BigDecimal`。材料未给资产精度，离线适配器采用 BTC 8 位、ETH 18 位、其他资产 6 位，舍入模式为 `DOWN`。过期报价按原报价隐含美元单价和参考中间价计算相对偏差，`<= 1%` 继续，`> 1%` 重新报价。

## 9. 两层幂等

订单载荷重放与链上资金事件去重分开建模：

- 订单层使用 `orderId + payloadSha256`，相同内容可重放，不同内容进入冲突处理。
- 资金层使用 `network + txHash + transferIndex`，原子 `putIfAbsent` 保证同一进程并发只能有一个 owner。

当前离线实现使用进程内存，足够演示单次批处理和并发原子性，但不能跨进程恢复。生产版本应把两个端口替换为具备唯一索引和事务的数据库适配器；这是明确保留的基础设施替换点。

## 10. 执行和工单

默认是 `DECISION_ONLY`，不会连接真实银行或链上 Provider。非自动处置在审计成功后通过幂等 recording adapter 创建工单；模拟资金网关只有在聚合已审计且仍满足执行资格时才接受请求。真实付款、发币、退款和人工解冻故意不实现。

## 11. 批处理顺序

当前 runner 保持 JSONL 输入顺序，确保 O-002 先取得 tx `0xa1`，O-013 稳定成为重复 no-op。`maxConcurrency` 是未来有序并发执行器的配置边界，目前默认值为 1。生产扩展时必须先把资金事件 claim 移到持久化事务中，不能为了吞吐牺牲确定性和幂等。

## 12. 故意没有做的内容

- 真实资金执行、退款、合规解冻。
- 真实 KYC、链节点、银行、VASP 目录和 LLM Provider。
- Web UI 和 REST API；题目交付要求是 CLI 与 JSONL。
- 分布式队列、跨进程状态恢复和指标后端。

下一步优先级是持久化幂等/聚合状态、工具超时与有限重试、可恢复批次 checkpoint，随后才是有界并发和真实 Provider 适配。
